## Что это за проект

Локальное веб-приложение (FastAPI) для методиста кафедры: загружает файлы
расписания (индивидуальные занятия .xls/.xlsx + групповые .doc/.docx),
сводит в единую базу и ищет накладки (преподаватель/аудитория/студент в
двух местах одновременно). Работает как обычный сайт (localhost:8000) или
как собранный PyInstaller `.exe` — методисту не нужен Python/git.
Подробности архитектуры — в `README.md`, он поддерживается в актуальном
состоянии, читай его тоже.

## Правила работы в этом репозитории

- Весь код, комментарии, UI, коммит-сообщения — на русском.
- Коммитить и пушить сразу в `main`, без промежуточных веток/PR, если
  пользователь явно не попросит иначе.
- **Перед пушем всегда**: прогнать тесты (`cd backend && <venv>/bin/python -m pytest tests/ -v`)
  и, если менялся UI/поведение — поднять сервер и проверить вживую в
  браузере (в этой среде уже есть Chromium — `/opt/pw-browsers/chromium-*/chrome-linux/chrome`,
  Playwright ставится через pip). Скриншоты того, что получилось,
  отправлять пользователю через SendUserFile — он это ценит и просит
  сам, когда забываешь.
- После ручной проверки — обязательно убрать тестовые данные
  (`data/`, `config/` в корне репозитория при разработке из исходников)
  перед коммитом, чтобы не закоммитить мусор случайно.
- Один тест падает всегда и не по нашей вине:
  `tests/test_pipeline_errors.py::test_corrupt_legacy_doc_is_skipped_not_crashed`
  — в этой линукс-песочнице нет Word/LibreOffice для конвертации `.doc`.
  На Windows у методиста должен проходить. Не пытайся его "чинить".
- **Релиз** (`APP_VERSION` в `backend/app/version.py`, сборка `.exe` через
  `build_exe.bat`, публикация GitHub Release с тегом `vX.Y.Z` и
  прикреплённым `.exe`) — ВСЕГДА делает сам пользователь на своей Windows-
  машине. У Claude здесь нет ни Windows (PyInstaller не кросс-компилирует),
  ни инструмента для создания GitHub Release. Можно (и нужно) поднять
  `APP_VERSION` по его просьбе и запушить это одной строкой — саму
  сборку и публикацию не делать, а объяснять шаги.

## Технические детали, которые легко забыть

- **Расположение данных зависит от режима.** При разработке из исходников
  (`is_frozen() == False`) `data/` и `config/` лежат в **корне репозитория**
  (`cafedra-schedule/data`, `cafedra-schedule/config`), НЕ в `backend/` —
  легко ошибиться и чистить не ту папку (уже наступали на эти грабли).
  В собранном `.exe` — `%LOCALAPPDATA%\CafedraSchedule\` (не рядом с
  `.exe`!), с автопереносом старых данных при первом запуске новой версии
  (`app/paths.py:migrate_legacy_storage`).
- `config/cabinets.json` (реестр кабинетов) хранится ОТДЕЛЬНО от `data/`
  намеренно — переживает удаление истории проверок.
- `Lesson` — dataclass с `eq=True`, поэтому **нехэшируемый** (`__hash__`
  автоматически `None`). Нельзя класть его в `set()`/использовать как ключ
  словаря — сравнивай через `==`/`is` напрямую, не через множества.

## Что уже сделано (свежее сверху)

1. **Интерактивная сетка занятости кабинета** — цветной календарь-таблица
   (дни × время), ячейки: свободно (белая) / занято (голубая) / накладка
   (красная, tooltip при наведении с обеими сторонами конфликта) / нет
   слота в этот день (штриховка). Переиспользует `find_conflicts()` из
   `conflicts.py` для тех же самых накладок, что и в основном отчёте.
2. **Данные в AppData, а не рядом с `.exe`** — `%LOCALAPPDATA%\CafedraSchedule\`,
   с автомиграцией со старого места.
3. **Вкладка "Кабинеты"** — реестр кабинетов кафедры (ручное добавление/
   удаление + подсказки из индивидуальных занятий текущей проверки),
   схема данных с заделом на несколько кафедр на будущее (пока не нужно,
   не строй UI выбора кафедры без явной просьбы).
4. **Очистка старых загрузок + удаление проверки + экспорт в Word + даты
   по-человечески** — сырые файлы больше не копятся вечно в `data/uploads/`,
   есть кнопка "Удалить эту проверку", кнопка "Скачать отчёт в Word"
   (`python-docx`, уже в зависимостях), даты в "Недавние проверки" в
   локальном времени и читаемом формате.
5. **Фильтр отчёта по ФИО** — выпадающий список (не текстовый поиск!)
   "Показать только по ФИО" на странице отчёта, точное совпадение (не
   подстрока — выбор всегда из готового списка). "Всё в порядке", если
   у выбранного человека накладок нет.
6. **Самообновление `.exe`** — кнопка "Скачать и установить" в баннере на
   главной, скачивает новый `.exe` и подменяет себя на месте (bat-хелпер
   ждёт завершения процесса, см. `app/self_update.py`). Работает только
   для frozen `.exe` на Windows.

## Открытые вопросы / сознательно не сделано

Не берись за эти пункты без явного запроса — они требуют вводных от
пользователя, которых пока нет:

- **Формат 3** (мастер-раскладка по аудиториям) не парсится — нужен хотя бы
  один реальный файл-образец, его пока не давали.
- **Ростер подгрупп** — нет данных о составе подгрупп ни в одном формате,
  накладки "студент × подгруппа" всегда помечаются "требует проверки".
  Нужно решить, как методист будет передавать состав (отдельный файл?
  вручную в интерфейсе?).
- **Сопоставление людей по ФИО без уникального ID** — риск ложной накладки
  у тёзок с одинаковыми инициалами. Пока не подтверждённая на практике
  проблема (спрашивали — реальных случаев не было), не чинить вслепую.
- **Несколько кафедр** — `cabinets.py` уже хранит данные в форме
  `departments`, но UI переключения между кафедрами не строился (нужна
  вторая реальная кафедра, чтобы понимать, что там за кабинеты и как
  переключаться).
