# Проверка расписания — поиск накладок и сверка

Программа для проверки и сверки расписания занятий: загружает несколько
файлов расписания (индивидуальные занятия .xls/.xlsx, групповые .doc/.docx),
сводит их в единую базу и находит накладки:

- преподаватель/концертмейстер одновременно в двух местах;
- одна аудитория занята дважды;
- студент должен быть в двух местах одновременно (индивидуальное ⨯ индивидуальное,
  индивидуальное ⨯ групповое).

Результат — отчёт в браузере с разбивкой по типам накладок и выгрузкой в Excel.

Изначально писалась под конкретный формат файлов кафедры фортепиано одного
вуза (см. `individual.py`/`group.py` в структуре ниже), но сама идея и
алгоритм поиска накладок не привязаны к музыкальному образованию — под
другой формат исходных файлов нужно будет донастроить только парсеры.

## Для методиста: как запустить

Проще всего — готовый `.exe`, ничего устанавливать не нужно:

1. Скачайте `CafedraSchedule.exe` (страница [Releases](../../releases) этого репозитория).
2. Запустите двойным кликом — откроется браузер на `http://127.0.0.1:8000`.
3. На странице загрузите файлы расписания и получите отчёт.

Чтобы закрыть программу — закройте открывшееся окно консоли.

**Важно:** для чтения старых файлов `.doc` на компьютере должен быть установлен
Microsoft Word (или LibreOffice) — это внешняя программа, её нельзя "зашить"
внутрь `.exe`.

Альтернатива без `.exe` — запуск из исходников через git (см. `Первый запуск
(один раз).bat` и `Обновить и запустить.bat` в корне репозитория).

## Для разработки

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
```

Запуск сервера в режиме разработки (с автоперезагрузкой):

```bash
cd backend
..\.venv\Scripts\uvicorn.exe app.main:app --reload
```

Откройте `http://127.0.0.1:8000`.

### Тесты

```bash
cd backend
..\.venv\Scripts\python.exe -m pytest tests/ -v
```

### Сборка standalone .exe

```bash
cd backend
build_exe.bat
```

Результат — `backend\dist\CafedraSchedule.exe`. Перед релизом поднимите
`APP_VERSION` в `backend/app/version.py`, соберите, запушьте, создайте на
GitHub Release с тегом того же номера (`vX.Y.Z`) и приложите `.exe`
файлом к релизу — тогда работающие копии программы сами покажут
методисту баннер о новой версии с кнопкой «Скачать и установить»: программа
скачает новый `.exe` и подменит себя на диске сама, без второй копии рядом
(см. `backend/app/self_update.py`). Важно приложить именно `.exe`-файл к
релизу — без него баннер покажет только ссылку на страницу релиза для
ручного скачивания.

## Структура проекта

```
backend/app/
  parsers/
    individual.py   — Формат 1: индивидуальные занятия (.xls/.xlsx)
    group.py        — Формат 2: групповые занятия (.doc/.docx)
    dedup.py        — сведение почти-дублей между листами/файлами
    doc_convert.py  — конвертация .doc → .docx (через MS Word/LibreOffice)
    common.py       — нормализация ФИО/группы/аудитории/времени
  conflicts.py      — алгоритм поиска накладок
  pipeline.py       — сборка полного набора занятий из двух форматов
  db.py             — хранение импорта в SQLite
  main.py           — FastAPI: загрузка, отчёт, экспорт в Excel
  update_check.py   — проверка новых версий через GitHub Releases
  self_update.py    — скачивание и установка обновления "на месте" (замена .exe)
  cabinets.py       — реестр кабинетов кафедры + сетка занятости (вкладка "Кабинеты")
backend/tests/      — pytest, регрессионные тесты на реальные кейсы кафедры
backend/desktop_app.py, build_exe.bat — сборка в standalone .exe
```

## Известные ограничения

- Формат 3 (мастер-раскладка по аудиториям) не парсится — это производный
  документ, избыточный относительно Форматов 1 и 2.
- Накладки "студент ⨯ групповое" для занятий, помеченных как "подгруппа",
  помечаются "требует проверки" — нет данных о составе подгрупп ни в одном
  из форматов.
- Сопоставление людей идёт по совпадению ФИО (с учётом опечаток), без
  уникальных идентификаторов — тёзки с одинаковыми инициалами теоретически
  могут дать ложную накладку.
